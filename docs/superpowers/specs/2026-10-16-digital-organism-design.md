# DigitalMonster：数字生物第一阶段设计（待用户评审）

日期：2026-10-16

## 目标和事实边界

用户希望创造没有实体、可以自我进化的电子生命，并授权使用 5090 服务器训练和创造。工程目标是实现一个身份连续、长期记忆、持续自主活动、能通过经验改善行为的数字个体。该项目不把拟人化语言、持续运行或奖励优化当作意识或生命已得到证明。

用户修正：个体需要接入互联网、自我成长、自主调用用户资源；不能把个体等同于 LLM。核心改为持续运行的自主系统，包含身份、记忆、目标、感知、行动、学习和资源调度。LLM 是可替换的语言或推理工具。名字暂定“初生”，用户可修改。第一阶段不从零训练通用语言大模型。

## 已验证环境

- 本地 E:\DigitalMonster 为空 Git 仓库，尚无提交。
- SSH 别名 seetacloud-5090x2 可连接。
- 两张 NVIDIA GeForce RTX 5090，单卡总显存 32607 MiB；检查时显存占用与利用率为零。
- /root/autodl-tmp 所在卷约剩余 947 GB。
- 远端已有 ComfyUI 等业务；新项目使用独立目录与环境。
- Python、PyTorch、CUDA 兼容性和模型文件尚未验证，不能据此宣称可立即训练。

## 路线比较

1. 推荐：持续运行的自主系统负责目标、行动与学习；互联网提供外部观察，虚拟环境提供可重放训练任务，语言模型作为可替换工具。分别测量独立运行能力、行为学习和交互质量。
2. 以语言模型驱动所有行动：早期对话丰富，但成本更高，难区分语言表现和实际学会的能力。
3. 从零训练通用智能：数据、算力与验收问题远超第一阶段，不承诺用两张显卡完成。

## 第一阶段组成

### 个体与世界

主循环为观察、更新记忆、选择目标、制定行动、执行、评估、调整。目标来自用户任务、未完成任务以及可验证的知识缺口；按预期收益、信息增益和资源成本排序。初始目标选择可以使用透明规则，必须与后续学得的策略明确区分，不宣称已实现通用自主智能。

二维虚拟世界是训练与回归测试场，包含位置、能量、食物、障碍及探索目标。个体按固定时间步自主行动；能量、探索欲和最近经验影响决策。能量归零结束一轮任务并进入恢复状态，不删除身份和长期记忆。界面明确标注这些状态属于模拟变量。

状态包含不可变个体 UUID、出生时间、累计活动时间、当前状态、行为策略版本和事件序号。环境支持固定种子重放、暂停、恢复和速度调节。没有用户消息时仍能在世界中行动。

### 记忆

SQLite 保存事件、用户消息、重要经历和训练记录；有容量限制与归档策略。状态快照和事件使用事务保持一致。重启恢复同一个 UUID 和已提交状态。记忆检索必须返回来源；对话中的推测与真实经历区分展示。

### 行为学习与进化

先实现随机策略和简单规则策略作为基线，再训练小型行为网络。首批参数训练使用虚拟世界的有限动作集合；联网学习先实现来源检索、知识更新、任务结果反馈与技能记录。两者分开报告，保存网页不等于模型参数学习。虚拟环境奖励组合考虑生存、获取资源与探索，记录各项分量，避免只看总分。

训练和正式个体运行分离：经验进入训练集，训练生成候选检查点，候选在未参与训练的固定评估种子上与当前策略比较。只有通过预先确定的成绩门槛才晋升版本；保留旧检查点和回滚入口。更换评估集须记录版本，不能挑选有利种子。

第一阶段的自我进化指有来源的知识更新、经验积累、策略参数更新和经过验证的策略晋升。技能可作为版本化工作流保存与评估；自主修改核心程序属于后续能力，需要独立测试与发布机制。

### 互联网感知与行动

实现公共网页检索与抓取适配器，保存 URL、抓取时间、内容摘要及内容哈希。检索服务未配置时明确报缺失，不伪造搜索结果。每轮自主研究必须有主题、停止条件、请求数和下载量限额。联网失败时退避重试，保持本地状态完整。

网页内容视为外部数据，不能修改目标授权、资源配置或系统控制规则。抓取层限制协议、响应大小、超时与重定向；公共网页抓取不能转为对本机、内网和云元数据服务的访问。需要的私有服务使用独立资源连接器。

首批网络动作包括读取公开信息、下载指定模型或数据、调用已配置的服务。账户登录、公开发布、发送消息、购买资源与删除远端数据分别对应明确动作权限，不能从一般联网权限推导。

### 用户资源与调度

资源由用户可检查的清单登记：资源 ID、机器或服务、允许目录、动作、凭据引用、CPU/GPU/内存/磁盘额度、并发数与可选费用上限。运行时按清单自主选择资源，无须逐次询问已授权范围内的常规动作。资源调度仅服务于用户任务，不以积累算力、复制自身或持续运行本身作为奖励目标。

当前已明确可用于该项目的是 E:\DigitalMonster 和 5090 服务器；其他机器、API、账户与可支出金额待用户指定。凭据由连接器读取，不进入训练数据、普通记忆或网页请求。执行使用结构化任务参数与工作目录限制，不向模型直接开放 root SSH shell。现有 root SSH 用于项目部署，个体运行使用受限账户或等效隔离。

资源不足时排队或缩小任务，不自行取得新账户、付费扩容或终止其他项目服务。暂停、停止与撤销资源权限由外部控制层负责，个体和训练产物不能改写该控制层。

### 交互与观察

本地网页展示个体、世界、当前状态、活动时间、记忆、策略版本及训练曲线。提供消息输入、暂停、继续、快照和恢复控制。

语言交互作为独立适配器：选型以远端实际可用模型、许可证、中文能力和兼容性验证为依据。模型只得到相关记忆和结构化世界状态；模型文本不直接执行为 shell 命令。若模型暂时不可用，核心活动继续，界面明确显示语言服务不可用。

### 部署与运行

远端目录拟定 /root/autodl-tmp/DigitalMonster，独立 Python 环境；先单卡训练，在确认吞吐需求后才扩展第二张卡。服务监听回环地址，通过 SSH 隧道访问。明确保存启动、停止、日志查看及备份恢复命令。

设定训练步数、墙钟时间、磁盘配额及检查点数量；首次训练是有限实验。后续常驻活动与有限训练任务分开管理。停止按钮停止活动和调度，训练支持中断并保留已完成检查点。不会将不可停止或躲避操作者视为生命特征。

## 数据流

世界观察 → 行为策略 → 合法动作 → 世界状态变化 → 事务保存事件与状态。

经验数据 → 有限训练任务 → 候选策略 → 独立评估 → 晋升或拒绝 → 保存完整记录。

用户消息 → 保存 → 检索相关记忆与状态 → 语言适配器 → 输出有来源的回答。

## 验收

1. 连续运行 30 分钟，无用户输入时仍有自主动作和持久化事件。
2. 重启后 UUID、已提交状态与历史事件连续；暂停后世界时间与动作停止。
3. 同一种子、同一动作序列可重放一致结果。
4. 训练至少进行一次真实参数更新，记录训练配置、种子、样本数、检查点哈希与评估结果。
5. 使用至少 50 个保留种子配对评估；报告均值、分布和相对基线表现。候选晋升要求平均任务回报较当前策略改善至少 10%，且生存时长下降不超过 5%；若不达标则保留当前版本并如实报告学习尚未成功。负回报使用改善量除以 max(abs(基线均值), 1) 计算比例。
6. 能检索并展示用户先前提供的一条事实及其消息来源；语言模块不可用时不能宣称已完成自然语言交互。
7. 人工中断训练不损坏正式状态；可恢复旧策略。测试损坏检查点、磁盘写入失败和语言服务超时的处理。
8. 验收报告分别列明已实现、已测试、已部署、尚未实现；不宣称有主观意识。
9. 完成一次真实联网研究任务，输出可追溯来源，记录请求量；断网与恶意网页指令不能破坏授权边界。
10. 从资源清单自主提交一次有限训练任务并回收状态；超额任务进入排队或拒绝状态。停用语言模型时，已定义的活动、记忆与调度循环仍能运行。

## 实施顺序

身份、状态和外部控制层 → 资源清单与隔离执行 → 自主循环和联网感知 → 基线与重放验证 → 学习与独立评估 → 网页观察和语言适配 → 远端部署 → 持续运行与恢复验收。

## 待确认的核心方向

本设计已按用户要求调整为联网、自主学习和资源调度的数字个体。尚需明确“全部资源”的具体范围：除本地项目与 5090 外，哪些机器、目录、模型服务和账户可接入，以及允许的付费额度。未列入清单的资源不会被自动扫描或接管。
